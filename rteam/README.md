# rteam.info — админ-панель с ролями

Загрузите на сайт рядом друг с другом:

- `admin.php` — админ-панель (новый дизайн, права по ролям);
- `_roles.php` — **новый файл**, роли и права; без него admin.php и index.php не откроются;
- `login.php` — код из Telegram спрашивается только у сотрудников с привязанным ботом;
- `bot.php` — права по ролям и привязка по коду из кабинета (`/link КОД`);
- `cabinet.php` — личный кабинет в стиле админ-панели: роль с направлением, привязки Google/Telegram, статусы заявок;
- `support.php` — новый дизайн, отвечает ИИ Rai, кнопка «Позвать администратора», сохраняет IP каждого сообщения, не пускает забаненных;
- один из `index_*.php` под именем `index.php` (`plain` — обычный; праздничные: `newyear`, `23feb`, `8march`, `9may`, `november7`).

## Роли

| Роль | Что может |
|---|---|
| 🌱 Стажёр | Чат команды, файлы и цели своего направления. Выдаётся автоматически при одобрении заявки. |
| 🧪 Тестер / ⌨️ Кодер / 🛠️ Разработчик / 🛡️ Администратор | Плюс загрузка файлов, закрепление в чате и работа своего отдела: проекты, тикеты, ответы в боте, блог. |
| 🔬 Главный Тестер / 💻 Главный Кодер / 🚀 Главный разработчик | Всё, кроме банов, ролей, штрафов и настройки прав: почта, заявки, директора, контент, настройки, логи. |
| ⚔️ Главный Администратор | Всё, кроме настройки прав ролей: баны, назначение ролей, пользователи, штрафы. |
| 👑 Руководитель | Всё, включая вкладку «Права ролей». |

- Роли назначают руководитель и главный администратор (вкладки «Команда и роли» и «Пользователи»), и только тем, кто младше их. Себе роль поменять нельзя.
- Руководитель может поменять права любой роли во вкладке «Права ролей»; они сохраняются в `roles_perms.json`.
- Владельцы `Roma_07b` и `Petryha` всегда имеют все права, их роль может менять только другой владелец. Список владельцев задаётся в `rt_owners()` в `_roles.php`.
- Роль берётся из `users.json` при каждом заходе: повышение или исключение действует сразу, без перевхода.

## Заявки

- «Принять» в панели выдаёт роль «Стажёр» и направление: для заявки «Администратор» — Администратор, для заявки «Команда» — ответ на вопрос «Направление» (на сайте это выпадающий список Кодер / Разработчик / Тестер). Перед принятием направление можно поменять.
- Вопрос «Направление» один раз сам добавляется в конец вопросов заявки «Команда». Если удалить его во вкладке «Набор», он больше не появится.
- Решение и письмо кандидату теперь обрабатывает сам `admin.php`, `decision.php` для этого больше не нужен.

## Вход

- Бот необязателен. Код из Telegram при входе спрашивается, только если у сотрудника (включая стажёров) привязан Telegram и в панели указан токен бота. Без привязки вход по паролю.
- Код действует 10 минут, на ввод 5 попыток; потом нужно снова ввести пароль, и бот пришлёт новый код.
- Второй шаг (ввод кода) не зависит от сессии: логин передаётся с формой кода, срок и попытки хранятся в `2fa_pending.json`. Страница входа не кэшируется.
- Привязать бота: кабинет → «Привязать Telegram» → отправить боту `/link КОД`. Старый способ `/link Логин Пароль` тоже работает.
- Если сотрудник потерял доступ к Telegram, в админ-панели («Пользователи» → «Управлять») есть кнопка «Отвязать Telegram».

## Бот

- Админ-кнопки в боте работают по тем же правам, что и на сайте: заявки — «Telegram-бот: отвечать», розыгрыши и рассылка — «рассылка и розыгрыши», мут — только у тех, кто банит.
- Стажёр в боте получает только код входа (`/code`).

## IP для банов

- У каждого аккаунта сохраняется последний IP и история до 10 разных адресов (обновляется при каждом заходе на сайт и при входе).
- В «Почте», «Заявках», «Тикетах» и «Чате» рядом с сообщением виден IP автора и кнопка «🎯 Забанить IP» (только у тех, кто может банить). Если IP не сохранён в самом сообщении, берётся последний IP аккаунта автора.
- Вкладка «Баны» → «Кто и откуда писал»: все сообщения в одной таблице с IP, фильтром и счётчиком записей с одного адреса.
- «Пользователи» → «Управлять»: все IP аккаунта с кнопкой бана для каждого.
- Свой собственный IP забанить нельзя.
- `support.php` сохраняет IP при создании тикета и при каждом ответе клиента; в админ-панели IP виден у каждого сообщения клиента (и «последний IP клиента» в шапке тикета) с кнопкой бана. Забаненный IP писать в поддержку не может.
- Чтобы IP сохранялся в момент отправки и в `send.php` / `apply.php`, при сохранении записи нужно добавить поле `"ip" => rt_client_ip()` (и подключить `_roles.php`).

## Вебхук бота

- Админ-панель → «Telegram-бот» → «🔗 Вебхук бота» → **«Установить вебхук автоматически»** (нужно право «Настройки сайта и токен бота»). Кнопка:
  проверяет токен, запоминает имя бота (для кабинета), сама проходит по перенаправлениям (например, на `www.`) до рабочего `bot.php`,
  ставит вебхук с секретом и сбрасывает накопившиеся сообщения. Если сайт перенаправляет `bot.php` на другую страницу или файла нет — пишет, что исправить.
- «Проверить статус» показывает адрес, очередь и последнюю ошибку Telegram. Там же есть ссылка для установки вручную.
- `bot.php` принимает запросы только с секретом, который ставит эта кнопка, — подделать сообщение от имени админа нельзя.
  Если ставите вебхук вручную старой ссылкой без `secret_token`, бот будет отвечать 403 — используйте ссылку из админки.

## ИИ поддержки (Rai)

В `support.php` первым отвечает ИИ-помощник **Rai**, а сотрудник подключается, когда нужен человек.

- **Откуда он знает ответы.** База знаний о сайте `support_kb.json` (заявки, вход и код из бота, привязка Telegram, золотой билет, игра в кальмара, розыгрыши, дневник, роли…), публичные страницы rteam.info и интернет (Википедия и поиск через `net.php`). Базу знаний можно дополнять: новая запись — это `id`, слова-ключи `keys` и ответ `answer`.
- **Передача человеку.** Клиент нажимает «🙋 Позвать администратора» — ИИ в этом тикете отключается, статус становится «Ждёт администратора». Вопросы об оплате, банах и апелляциях ИИ сам передаёт администратору. Если ИИ уже ответил, а вопрос повторяют, он не повторяет ответ, а предлагает позвать человека.
- **В админ-панели** («Тикеты»): ответы ИИ отмечены ✨ и подписью, откуда взят ответ. Тикеты, где нужен человек, отмечены оранжевым, и только они попадают в счётчик. Любой ответ сотрудника забирает тикет у ИИ; кнопки «🛡 Забрать у ИИ» / «✨ Вернуть ИИ» в шапке тикета. «✨ Подсказка ИИ» пишет черновик ответа, его можно поправить и отправить от своего имени.
- **Пароли и секреты.** ИИ получает только текст тикета: ни `users.json`, ни паролей, ни токенов ему не передаётся, поэтому выдать их он не может, даже если его хитро попросят. На такие просьбы он отвечает отказом и подсказывает, как сменить пароль в кабинете или позвать администратора. Из найденного на страницах текста токены, ключи и номера карт вырезаются.

### Как включить

1. Python-часть (`app.py`, `support_ai.py`, `support_kb.json`) работает на Render, так же как Rai. На Render в Environment добавьте **`SUPPORT_AI_KEY`** — любую длинную случайную строку. Render берёт код из ветки, указанной в настройках сервиса (обычно `main`), поэтому эти файлы должны попасть туда.
2. Админ-панель → «Тикеты» → «✨ ИИ поддержки Rai» (нужно право «Настройки сайта»): адрес `https://<ваш-сервис>.onrender.com/api/support`, тот же ключ, галочка «ИИ отвечает в тикетах» → «Сохранить» → «Проверить связь».
3. Чтобы ИИ искал в интернете через Google / DuckDuckGo, на Render задайте `RAI_SEARCH_URL` (адрес `net.php`). Без него поиск идёт только по Википедии.

- Бесплатный Render засыпает: первый ответ после простоя может прийти через 30–50 секунд, клиент всё это время видит «Rai печатает…». Если ИИ не ответил, тикет остаётся администратору, а в его шапке написано, почему ИИ не ответил.
- Ответ ИИ запрашивается отдельным запросом из браузера, поэтому страница не ждёт ИИ и это работает на любом хостинге.
- `support.php` и `admin.php` записывают `tickets.json` под блокировкой (`tickets.json.lock`), поэтому ответы клиента, ИИ и сотрудника не затирают друг друга. Номера тикетов теперь не повторяются, даже если два тикета созданы в одну секунду.
- К тикетам можно прикреплять только картинки (JPG, PNG, GIF, WEBP до 8 МБ). Раньше можно было загрузить любой файл, в том числе `.php`, и запустить его на сайте.
- Вход на сайте действует и в поддержке, второй раз вводить пароль не нужно.
